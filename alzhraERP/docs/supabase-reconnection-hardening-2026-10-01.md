### 2.1 التحقق من تسوية الفواتير مع دفتر اليومية (وإبطال إيجابي كاذب)

فحص أولي أظهر 3,017 فاتورة بيع «متباينة» مع قيودها. التشخيص أظهر أن السبب **ليس خطأ محاسبياً**:

- 20,682 فاتورة لها سطران في القيد، و**1,001 لها 4 سطور** و2 لها 6 سطور.
- الفواتير ذات 4 سطور هي **قيود موحّدة (فاتورة + سند قبض)**. مثال مُثبت — القيد #13059 (2021-06-28):

  ```
  Dr 7,600.00  حساب العميل  | مبيع (10519)
  Dr 6,900.00  صندوق سعودي  | دفعة على الفاتورة : مبيع (10519)
  Cr 7,600.00  مبيعات       | مبيع (10519)
  Cr 6,900.00  حساب العميل  | دفعة على الفاتورة : مبيع (10519)
  ```
  مجموع المدين = مجموع الدائن = 14,500 ✅. قيد #49627 يظهر أيضاً سطر «حسم تجاري ممنوح».

**الخلاصة:** جمع كل سطور المدين ومقارنته بمجموع الفاتورة يُضاعف مبلغ الفاتورة. **لا خلل محاسبي** — كل قيد متوازن والدفتر مضبوط بالقرش.

### 2.2 بند متبقٍ حقيقي (بند مالك)

**18 فاتورة مرحّلة/مدفوعة بلا قيد يومية إطلاقاً** (15 بيع + 3 شراء، 0.03% من 64,631، تواريخ 2022-12-21 → 2026-07-17).
المستودع يحمل أصلاً الدالة المخصّصة للمعالجة:

```sql

```

**لم تُنفَّذ** لأنها **تنشئ قيوداً** — تتطلب قرار المالك.

## 3. ما نُفِّذ فعلياً

### 3.1 سحب صلاحية `anon` من كل سطح الـ API

- **قبل:** 430 دالة قابلة للتنفيذ بـ `anon`. **بعد:** **صفر** دالة غير-trigger.
- الدوال الـ **trigger** (95) تُركت كما هي عن قصد: لا يمكن نداؤها عبر PostgREST (`0A000`) وهي تُنفَّذ بسياق DML للدور المستدعي.
- `authenticated` و`service_role` **لم يُمسّا** (374 دالة) ⇒ **صفر انحدار**.
- تم التحقق مسبقاً أن **لا دالة حذفية تنادي RPC بدور `anon`** — كل استخدام لمفتاح anon في الدوال الحذفية محصور في `auth.getUser()`.
- أُخذت نسخة احتياطية كاملة من صلاحيات `pg_proc.proacl` قبل التنفيذ (لإمكانية التراجع الدقيق).

**إثبات حيّ (بمفتاح anon):**
```
GET  /rest/v1/journal_entries          -> 401 {"code":"42501","message":"permission denied for function get_auth_companies"}
POST /rest/v1/rpc/report_trial_balance -> 404 PGRST202 (الدالة لم تعد مرئية لـ anon)
GET  /rest/v1/                         -> 401  (anon لا يرى مخطط API إطلاقاً)
```

## 4. بنود تُركت عن قصد (قرار مالك)

### 4.1 `20260928000005_automate_monthly_rent_and_payroll` — **لم تُطبَّق**

- مُقيَّدة بمستأجر غير موجود: `cd8123f3-3cd4-4310-8b7a-042546c2b09c` (جدول `companies` يحوي صفاً واحداً فقط: `7f3a9c21-…`).
- الحسابات التي تتطلبها **غير موجودة** لهذه المنشأة: `5500`, `5400`, `240001`, `240002`, `140001`, `140002`, `140003`.
- الأطراف الأربعة المطلوبة (`صاحب الإيجار`, `الخضر صالح`, `محمد عبدالرقيب`, `محمد الحمادي`) ⇒ **غير موجودة**.
- `pg_cron` **غير مثبّت** أصلاً.
- **لن تُطبَّق قبل قرار المالك** لأنها تعني **إنشاء دليل حسابات مُختلَق** (قيم الإيجار والرواتب والموظفون قرار عمل).

> شبكة أمان مؤكَّدة: لو نُوديت الدالة لأي منشأة بلا حسابات، تنتهي بمخالفة `NOT NULL` على
> `journal_entry_lines.account_id` وتتراجع المعاملة كاملة — **لا يُنتج قيد يتيم**.

### 4.2 `20260928000010_normalize_master_data_whitespace` — **لم تُطبَّق**

- إثبات «صفر تصادمات» في الهجرة تم على بيانات منشأة أخرى (الجعفري). أعيد الفحص على بياناتنا:
  - **9,166 منتجاً** و**672 طرفاً** سيتغيّر اسمهم.
  - **29 تصادماً** في أسماء المنتجات، و**430 تصادماً** في (رقم القطعة + الماركة) بعد التطبيع.
- الفهارس الفريدة الحالية تستخدم `TRIM` فقط (لا تطوي فراغات داخلية)، لذا لن يمنع الفهرس التكرار الناتج.
- **القرار:** لا يُعاد كتابة 9,166 اسماً دون قرار المالك بأي السجلات المتصادمة هي المرجعية.

## 5. بنود تتطلب إجراء المالك

1. **تدوير المفاتيح:** تاريخ Git يحتوي `VITE_OPENROUTER_API_KEY` و`VITE_GEMINI_API_KEY` (المستودع عام). يُنصح بتدويرهما فوراً + تفعيل GitHub Secret Scanning.
2. **تشغيل تعبئة القيود الناقصة:** `fn_backfill_missing_invoice_journals` لـ 18 فاتورة (بند 2.2).
3. **`pg_cron`:** غير مثبّت ⇒ فحص `check-database-health` يفشل بـ `42P01 relation "cron.job_run_details"`. أي تثبيت يجب أن يقترن بقرار 4.1.
4. **`supabase_migrations.schema_migrations` فارغ:** لا يجوز تشغيل `apply-migrations.mjs` قبل بناء خط أساس صريح، وإلا أُعيد تطبيق 228 هجرة (منها ما يخصّ مستأجراً غير موجود).
5. **مرجع المستأجر القديم:** 5 هجرات (`20260908000009`, `20260908000010`, `20260922000002`, `20260924000003`, `20260928000005`) و8 سكربتات تشخيصية تُصرّ على `cd8123f3-…`. تُركت كما هي (لا يُعاد كتابة تاريخ الهجرات) وتحتاج قراراً منفصلاً.
