## 3. الميكانيزم — لماذا تظهر الفاتورة «موسومة خطأً»

```
المخزَّن في كل جداول المستندات = مبلغ الأساس (SAR)   ← total_amount / subtotal / unit_price / discount / tax
الوسم currency_code          = عملة تعامل العميل (YER / SAR / OMR)  ← صحيح
الدفتر المحاسبي               = يحمل الاثنين بشكل صحيح (debit_amount أساس / foreign_amount عملة)
```

النتيجة: أي شاشة تطبع `formatCurrency(total_amount, currency_code)` تُظهر **معادل الأساس** تحت رمز العملة الأجنبية ⇒ «159.84 ر.ي» بدل «72,000 ر.ي».

| الدليل | القياس | الخلاصة |
|---|---|---|
| أسعار البنود مقابل الكتالوج | وسيط نسبة YER = **0.969** (لا 410) | بنود الفواتير «اليمنية» مسعّرة بالريال السعودي |
| رأس الفاتورة مقابل الدفتر | `total_amount` يطابق عمود الأساس بنسبة **94–97%** | الرأس يحمل الأساس، الدفتر يحمل الاثنين |
| المصدر (الميزان) | وسيط `Bill.Total` لليمني = **166.27** (لا 410× السعودي) | الخلل موجود في الميزان قبل الترحيل، والترحيل نقل الوسوم كما هي |
| مطابقة الدفتر للموسوم (pass3) | **2,020** فاتورة YER «لا تطابق الأساس ولا المشتق» وكلها **مؤكَّدة في الدفتر** | التناقض في العرض وليس في القيد |
