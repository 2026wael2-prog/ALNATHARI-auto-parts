# تصحيح فواتير الإدخال + الجذر الحقيقي (2026-10-02)

## 1. 🔴 الجذر الحقيقي: مُشغِّل في القاعدة كان يقلب سعر الصرف

بعد قرارك بأن الخلل في «بعض الفواتير» لا في الكود، بحثت عن سبب يصيب **بعض** الفواتير دون غيرها، فوجدته:

**`trg_guard_currency_inversion_invoices` → `fn_guard_currency_inversion()`** كان ينصّ حرفياً:
```sql
IF NEW.currency_code = 'YER' THEN
  IF COALESCE(NEW.exchange_rate,1.0) = 1.0 THEN RAISE ... END IF;
  -- إذا تم إدخال المعدل المعكوس (مثل 0.00244 أو 0.0022) نحوله تلقائياً لمعدل السوق (مثل 410)
  IF NEW.exchange_rate > 0 AND NEW.exchange_rate < 1.0 THEN
     NEW.exchange_rate := ROUND(1.0 / NEW.exchange_rate, 6);   -- ← القلب القسري
  END IF;
END IF;
```

**المشكلة:** الاصطلاح المعتمد في **كل** بياناتك المُرحَّلة من الميزان هو أن `exchange_rate` = **قيمة الوحدة الأجنبية بعملة الأساس** (اليمني ≈ 0.0015–0.0094). أما هذا المُشغِّل فيعتبر أي سعر أصغر من 1 «معكوساً» ويحوّله إلى مقلوبه (0.00222 → **450**) — أي أنه يطبّق اصطلاحاً **مضاداً** لكل البيانات.

**الأثر المطابق لوصفك تماماً:**
- الفواتير **المُرحَّلة** (الأغلبية) سليمة — لم تمرّ بالمُشغِّل.
- أي فاتورة **تُنشأ أو تُحرَّر عبر التطبيق** يتغيّر سعرها قسراً إلى 450 ⇒ فيُقسَم مبلغها على ~415 (أو يُضرب) ⇒ **«بعض الفواتير فيها أخطاء والأغلبية صحيحة»**. هذا هو تفسير ملاحظتك بدقة.
- كما أنه **منع تصحيح** الفاتورة `:14030` (رفض المُشغِّل السعر 0.002222 وحوّله إلى 450.045 فتضارب مع قيد الحماية `chk_invoice_yer_exchange_rate`).

**الإصلاح المطبَّق:** أُعيدت كتابة الدالة لتطابق الاصطلاح الفعلي:
```sql
IF NEW.currency_code = 'YER' THEN
  IF COALESCE(NEW.exchange_rate,1.0) = 1.0 THEN RAISE ... END IF;
  IF NEW.exchange_rate > 1 THEN NEW.exchange_rate := ROUND(1.0/NEW.exchange_rate, 6); END IF;  -- تصحيح المعكوس
  IF NEW.exchange_rate <= 0 OR NEW.exchange_rate > 0.02 THEN RAISE ... END IF;                  -- نطاق منطقي
END IF;
```
أي: يحمي من السعر 1.0 ومن الانقلاب، لكنه **لا يقلب** الأسعار الصحيحة.
